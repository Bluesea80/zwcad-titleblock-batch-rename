# zwcad-titleblock-batch-rename · 图框批量改名工具

面向设计出图场景的 **DWG 图框批处理工具链**。一条龙完成
**改名 → 刷新图框信息 → 折行居中 → 存盘 → 关闭**，全程无人值守，逐张记录日志。

> **运行环境**：Windows + 中望 ZWCAD（2025 专业版实测通过）。
> **解压即用** —— 不需要 Python / Node / .NET，不需要管理员权限，不写系统目录。

---

## 1. 解决什么问题

设计图纸在历次复制、套用旧图的过程中，会堆积**多个历史项目的图框块定义**
（例如同一张图里同时存在 `20XXJX000SS-甲-S-A3-1`、`20XX-乙-S-A3-1`、`20XXJS000CS-乙-S-A3-1`），
而图面上真正插入使用的往往只有一个。手工逐张判断、改名、刷新图框、调格式，既慢又容易改错。

本工具按给定的**通配模式**定位候选图框块，再用**图面实例数**自动判定"哪个才是真正在用的"，
然后统一改名、调 iMIS 刷新图框信息、把超长项目名称折行居中，最后存盘关闭。

---

## 2. 流水线

对根文件夹下的每一张 DWG：

| 步骤 | 动作 | 说明 |
|---|---|---|
| ① | **改名** | 按通配模式匹配图框块并改名；新名可手填，留空则由工作包 XML 的项目编号自动生成 |
| ①b | **清理无用块定义**（可选，默认关闭） | 删除"匹配模式但图面实例数 = 0"的历史垃圾图框块定义 |
| ② | **刷新图框信息** | 调院内 iMIS 插件命令，并用对话框助手自动填入工作包 XML 路径 |
| ③ | **折行居中** | 把 `项目名称` / `项目名称1` 两个单行属性对按比例折行并竖向居中（刷新后文字会重生，故必须重跑） |
| ④ | **存盘** | 逐张保存 |
| ⑤ | **关闭** | 关闭文档，进入下一张 |

每张图独立完成 ①②③④⑤，单张失败只记日志、不中断整批。

### 图框块判定阶梯（核心逻辑）

```
按通配模式匹配到 N 个候选块
├─ N = 0                    → NOMATCH，跳过
├─ N = 1                    → 直接处理该块
└─ N > 1  统计每个块在图面的插入实例数（遍历模型空间 + 全部布局）
   ├─ 唯一一个有实例          → 改它（其余视为历史垃圾）
   ├─ 多个都有实例 + 填了「优先关键字」→ 在"在用者"里按子串再筛，唯一命中才改
   ├─ 多个都有实例 + 关键字无命中/命中多个 → MULTI_USED，跳过（不猜）
   └─ 都没有实例              → ALL_UNUSED，跳过（可交给 ①b 清理）
```

## 3. 快速开始

1. 把本仓库的 `TKGPR批量处理.hta`、`_tgkm_batchworker.vbs`、`_tgkm_openhelper.vbs`、`图框块批量改名.lsp`
   **放在同一个文件夹**（可含中文路径）。
2. 打开 ZWCAD，确认已加载院内 iMIS 插件并登录（第 ② 步依赖它）。
3. 双击 `TKGPR批量处理.hta`，填写参数，点 **【开始处理】**。
4. 页面下方黑框实时输出日志；同时会在目标根文件夹写入 `TKGPR日志_YYYYMMDDHHMMSS.txt`。

> **备用入口（HTA 打不开时）**：极少数电脑的终端管控 / EDR 策略会禁用 `mshta.exe`，此时双击 `.hta` 无反应或报错。
> 改双击同目录的 `TKGPR批量刷新.vbs` —— 它只依赖 `wscript.exe`，**处理逻辑、备份、日志与主程序完全相同**，
> 参数项也一致（同样写 `HKCU\Software\TKGM`）。差别只有交互形式：弹窗式问答（逐个弹输入框）、无实时日志窗，结果跑完一次性提示。

### 参数

| 参数 | 说明 |
|---|---|
| **根文件夹** | 要处理的 DWG 所在目录，递归含子文件夹 |
| **工作包 XML** | 第 ② 步刷新用；也可留空由程序自动查找。**「新块名」留空时，也用它取项目编号生成新块名** |
| **改名模式** | 通配模式，如 `*-S-A3-1` |
| **新块名** | 留空 = 按 XML 项目编号自动生成（推荐） |
| **优先关键字** | 仅当"多个图框都被图面用到"时生效，如填 `20XXJS000CS-乙`。留空 = 不干预 |
| **图框比例** | 居中位移按此缩放，默认 `1` |
| **清理无用的图框块定义** | 勾选才执行 ①b，默认关闭 |

参数自动记忆（注册表 `HKCU\Software\TKGM`），下次打开自动回填。

## 4. 日志状态码

第 ① 步每张图会给出明确状态，便于定位问题：

| 状态 | 含义 |
|---|---|
| `OK\|旧名 -> 新名` | 改名成功 |
| `ALREADY\|新名` | 图面在用的已是目标名，跳过（幂等） |
| `EXIST\|新名 已存在，用到的是 旧名` | 目标块名已被占用，跳过 |
| `NOMATCH\|无块匹配 …候选(N):xx,yy` | 没有任何块匹配该模式，附候选块名提示 |
| `MULTI_USED\|块A(3),块B(1)` | 多个匹配块且图面都在用，无法判定，跳过（附实例数） |
| `ALL_UNUSED\|块A(0),块B(0)` | 多个匹配块但图面都没用，跳过 |
| `NONAME\|` / `NOPAT\|` | 生成不出新名 / 未填模式 |

## 5. 安全设计

- **改前自动备份**：整批开始前把待处理图纸镜像到根文件夹下的 `备份_时间戳\`（保持相对路径），可整目录回滚。
- **幂等可重跑**：已正确的图显示 `ALREADY` 跳过；重复执行无副作用。
- **单张失败不中断**：某张图出错只记日志并继续下一张。
- **破坏性动作默认关闭**：清理块定义需主动勾选；且 `-PURGE` 会拒绝删除仍被嵌套引用的块（双保险）。
- **图面内容不动**：改名只改块定义名，不删除、不替换任何图元引用。
- **只写用户区**：注册表仅写 `HKCU`，临时文件仅写 `%TEMP%`，日志写目标文件夹。

| `HANDOFF.md` | 项目交接文档：架构、约束、踩坑全集、待办（含真实工程路径与项目编号） | ❌ 仅本地 |

> **入库约定（脱敏铁律）**：任何提交进本仓库的文件**不得出现真实项目编号、客户项目名、真实本机路径或用户名**；示例一律用占位符（如 `20XXJS000CS-乙-S-A3-1`）。
> 含真实工程数据的文件（`模板/`、`HANDOFF.md`、`_tgkm_openhelper.param` 等）由 `.gitignore` 挡在仓外，只保留在工作区。

### 架构与数据流

```
TKGPR批量处理.hta ──写参数──> 注册表 HKCU\Software\TKGM
        │                     %TEMP%\tkgm_batch.ini
        └──隐藏启动──> _tgkm_batchworker.vbs ──逐张──> ZWCAD COM
                                 │  Documents.Open / Activate / Save / Close
                                 │  SendCommand 驱动 LISP
                                 ├─> 图框块批量改名.lsp
                                 │     TKGREN 改名 → TKGPURGE 清理 → TKGFIX 居中
                                 │     结果写 %TEMP%\tkgm_*.flag
                                 └─> 刷新时派发 _tgkm_openhelper.vbs 填对话框
        <──轮询日志文件──────────┘
```

参数经 `注册表 + ini` 交接给引擎，引擎用 `SendCommand` 驱动 LISP，LISP 把结果以
**状态化 flag 文件**（`tkgm_ren.flag` / `tkgm_purge.flag` / `tkgm_fix.flag` / `tkgm_done.flag`）
回写，引擎读出后写日志。日志不状态化就无法定位问题——这是本工具排障的设计前提。

## 7. 关键技术约束（血泪版）

这些都是真机实测踩出来的，改代码前务必先读：

| 约束 | 说明 |
|---|---|
| 🔴 **禁止并行启动第二个 ZWCAD 实例** | GUI / COM / `/b` 都算，会与原会话抢配置与 COM 锁互卡 |
| 🔴 **ZWCAD 的 `ZxDbDocument`（ObjectDBX）不可用** | 进程内创建即死锁（`0x8007045A`）。批量改图只能走**编辑器内 COM**：`Documents.Open → Blocks → vla-put-name → Save → Close` |
| 🔴 **mshta 的事件绑定** | 内联 `onclick="SubName"` 与 `setTimeout "SubName"` 字符串调度**无法解析 VBScript 的 Sub 名**（报"对象不支持此属性或方法"）。必须 `element.onclick = GetRef("SubName")`、`setTimeout GetRef("Proc"), N` |
| 🔴 **mshta 的 `document.URL` 形态** | 本机返回 `file://E:\dir\中文.hta`（反斜杠 + 盘符直出），不是教科书的 `file:///E:/...`。自定位目录要两种形态都兼容，中文按 UTF-8 解 `%XX` |
| 🔴 **`wcmatch` 的 `~` 是取反符** | `(wcmatch f "~$*")` 意为"不匹配 `$*`"，不是匹配字面 `~$`。过滤临时文件用 `(= (substr f 1 2) "~$")` |
| 🔴 **LISP 的 `(command ...)` 只发给宿主图** | 不会发给 COM 打开的图；跨文档场景下 `vla-SendCommand` / `vla-get-Blocks` 返回 nil。故正确处理是"COM 打开 + 图内 LISP 执行" |
| 🔴 **别在脚本里直调 iMIS 的 .NET 插件命令** | 会崩 ZWCAD（PerDocumentCommandClass ArgumentNullException）。刷新只能走"LISP 发命令 + VBS 对话框助手" |
| **编码** | 所有 `.lsp` / `.vbs` / `.hta` 保持 **GBK + CRLF**，HTA 用 `charset=gb2312`，勿混入 `✔` 等非 GBK 字符（用 `√`） |
| **实例计数要遍历全部布局** | `ssget "_X"` 只搜当前空间，会漏掉布局里的图框；须用 ActiveX 遍历模型空间 + 所有布局 |

## 8. 已知限制

- 第 ② 步依赖院内 iMIS 插件；未安装或未登录时该步会超时跳过（其余步骤不受影响）。
- 一张图里**多个图框都被图面使用**时，工具不会擅自决定保留哪个；不填「优先关键字」就跳过并报 `MULTI_USED`，需人工看图定夺。
- 多版本 ZWCAD 共存时，COM ProgID 与插件注册可能不一致；切换版本后建议先跑 `TKGDIAG` 自检。
- 一次只应有一个工具实例驱动一个 ZWCAD 会话。
